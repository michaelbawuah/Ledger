# Authored LLVM pass and pipeline experiment — October 30, 2026

**Implemented and correctness validated.** An authored LLVM 18 pass removes one redundant load in Ledger's real `FastBook::process` function when placed early. The final [validated run](llvm18-20261030-01/validated-05/result.json) completed three fixed pipelines, each passing the same **15 CTest cases** and the same **100-seed × 1,000,000-command differential check**. Its [independent audit](llvm18-20261030-01-audit.json) passed with a complete command history. No runtime speedup is claimed.

## Compiler implementation and direct IR proof

[`LedgerLoadElim`](../../llvm/LedgerLoadElim.cpp) is a C++ LLVM 18 new-pass-manager plugin. Its `ledger-load-elim` function pass reuses an earlier scalar integer load only when the pointer SSA value, type and MemorySSA clobber match within one basic block. LLVM's alias-aware walker permits crossing a provably disjoint store and rejects a possibly aliasing write. Calls, fences, atomic/volatile operations and non-debug load metadata end availability. Replacements are discovered before mutation, deletions update MemorySSA, and changed functions invalidate analyses.

The retained [plugin test log](llvm18-20261030-01/plugin-ctest.log) records **25 structural functions**, four intended eliminations, MemorySSA recomputation, idempotence, malformed-pipeline rejection and equivalent `lli` execution over **4,096 values with four expected-value checks per value**, before and after transformation. The tools and plugin SDK are LLVM **18.1.3**.

The [direct IR inspection](llvm18-20261030-01/ir-inspection/inspection.json) applies the declared early prefix to the shared frontend, with a separate [inspection audit](llvm18-20261030-01-inspection-audit.json). In `ledger::FastBook::process(ledger::Command const&, ledger::EventBuffer&)`, the pass replaces an `i32` read of `%remaining107` with the surviving `%67` value before `EventBuffer::push`. That function has **81 loads before the custom pass and 80 afterward**. The [diff](llvm18-20261030-01/ir-inspection/FastBook-process.diff) and full before/after IR retain the rewrite. This post-run static inspection is separate from the engine validation arms.

## Fixed pipelines on the live engine

Every arm starts from identical `src/book.cpp` frontend IR: C++23, `NDEBUG`, `-O1 -Xclang -disable-llvm-passes -fno-strict-aliasing`. A CMake compiler launcher installs the transformed `book.cpp.o` before its Ninja compile edge completes. The runner extracts that member from `libledger.a` and verifies its exact hash. Other translation units use identical normal CMake Release/O3 builds.

| Arm | Explicit `opt` pipeline | Custom-pass loads removed | Final translation-unit loads |
|---|---|---:|---:|
| Baseline | `default<O2>` | not run | 377 |
| Early | `function(mem2reg,ledger-load-elim),default<O2>` | 1 | 378 |
| Late | `default<O2>,function(ledger-load-elim)` | 0 | 377 |

These are static IR counts. The early arm also moves `mem2reg` ahead of the standard pipeline, so its final IR difference cannot be attributed to the custom pass alone. LLVM's EarlyCSE/GVN implement stronger versions of this educational optimization. Zero late rewrites is a valid result; the counts establish neither a faster nor an optimal pipeline.
